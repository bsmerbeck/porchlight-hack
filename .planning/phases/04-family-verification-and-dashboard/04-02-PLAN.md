<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| This phone's `localStorage` → which `prompts/{memberId}` doc it subscribes to | Any phone that knows/guesses a `memberId` can pair as that member — explicitly accepted for a single-demo-household hackathon build |
| Browser (untrusted client) → WebAuthn platform authenticator | The authenticator itself, not this code, is the actual security boundary; this code only relays the ceremony |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Spoofing | Wrong/unpaired phone impersonating a member by guessing a `memberId` for `localStorage` pairing | medium | accept | `04-RESEARCH.md` Assumption A1: explicitly scope-appropriate for a single-demo-household hackathon build, not a production identity system; the actual verdict-changing action still requires a real passkey assertion or a valid single-use token (04-01, T-04-01) — a guessed `memberId` alone cannot mark a call verified |
| T-04-06 | Denial of Service (UX) | Autoplay/vibrate silently failing on iOS Safari | low | mitigate | Gesture-gated "Enable alerts" button (a real click) unlocks audio; `navigator.vibrate` calls are feature-detected and `.catch()`-wrapped; the full-screen visual modal is the channel that never fails (Task 2) |

</threat_model>
