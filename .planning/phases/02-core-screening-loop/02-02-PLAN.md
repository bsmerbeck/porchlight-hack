<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller's phone -> Twilio -> ElevenLabs -> `elevenlabsCustomLlm` | Untrusted network boundary; ElevenLabs is the only party expected to reach this endpoint |
| ElevenLabs -> `elevenlabsPersonalization` | Untrusted, no bearer check (call-start webhook, fires before any conversation exists) |
| Browser/emulator -> `forceVerdict` (onCall, no Firebase Auth) | Demo-only debug surface, ahead of Phase 4's real passkey-gated verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Spoofing / Elevation of privilege | `elevenlabsCustomLlm` | high | mitigate | `ELEVENLABS_LLM_TOKEN` bearer check via `defineSecret`, checked before `runTurn` is ever called (Task 1) |
| T-02-06 | Tampering | Prompt injection via caller speech | high | mitigate | `SYSTEM_PROMPT` hard rules (02-01) + Task 1's wire-shape lock test ensuring only the `reply` string ever reaches the SSE response — no system-prompt or raw-model-object leakage |
| T-02-07 | Spoofing | Forged `elevenlabsPersonalization` POST creating junk `calls/` docs | low | accept | Worst case is a junk `screening`-state doc; no PII exposure, cost bounded; acceptable for a one-night demo, flag for real auth if productionized |
| T-02-08 | Information Disclosure | `TWILIO_ACCOUNT_SID`/`TWILIO_AUTH_TOKEN` | high | mitigate | Bound only via `defineSecret` (reused from Phase 1's declaration, D-04), never logged, never sent to `apps/web` |
| T-02-09 | Elevation of privilege | `forceVerdict`/`endCall` (onCall, no Firebase Auth) | medium | accept | Per 02-RESEARCH.md's Known Threat Patterns: explicitly a debug/demo-only path ahead of Phase 4's real Firebase-Auth-gated verification; a leaked `callId` lets someone end/release one demo call, no broader blast radius |
| T-02-SC | Tampering | `twilio@6.1.1` npm install | low | accept | 02-RESEARCH.md's Package Legitimacy Audit: SUS/too-new-only, canonical `twilio/twilio-node` repo, zero postinstall scripts — same disposition as Phase 1, no blocking checkpoint needed |

</threat_model>

## Firebase/ElevenLabs/Twilio surfaces used / not used
- **Firebase used:** Cloud Functions v2 `onRequest` (`elevenlabsCustomLlm`, `elevenlabsPersonalization`) and `onCall` (`forceVerdict`), Secret Manager (`ELEVENLABS_LLM_TOKEN`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `ANTHROPIC_API_KEY`) via `defineSecret`.
- **ElevenLabs used:** Custom LLM (`elevenlabsCustomLlm`), Personalization webhook, `end_call` system tool, native Twilio phone-number import, static `first_message`.
- **ElevenLabs not used:** the `post_call_transcription` webhook / HMAC verification (`@elevenlabs/elevenlabs-js` is NOT installed) — 02-RESEARCH.md's Pitfall 6 explicitly recommends skipping it for the 4-hour build; CALL-05 is fully satisfied via inline `endedAt`/`outcome` writes in `runTurn` (02-01, AI-initiated end) and `endCall`/`forceVerdict` (this plan, external verdict) instead.
- **Twilio used:** REST `calls(sid).update()` for forced hangup/release (`endCall.ts`), native number import into the ElevenLabs agent (dashboard).
- **Twilio not used:** Twilio webhook signature validation — no Twilio webhooks are received directly; the native ElevenLabs integration owns that leg entirely.
