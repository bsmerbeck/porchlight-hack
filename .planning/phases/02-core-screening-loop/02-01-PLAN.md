<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (`/sim`) -> `startSimulatedCall`/`simulateTurn` (onCall) | Untrusted client input (`callerText`) crosses here, no Firebase Auth required |
| `simulateTurn`/`runTurn` -> Anthropic API | Our system prompt + full turn history crosses to a third-party LLM |
| Caller-controlled text -> `SYSTEM_PROMPT`-governed Claude reply -> `calls/{id}.turns[]` (later rendered on a real dashboard, Phase 4) | Adversarial input surface for prompt injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `runTurn` / `SYSTEM_PROMPT` | high | mitigate | Hard-rule guardrails in `SYSTEM_PROMPT` (never reveal PII, never agree to payment) + Vitest case asserting those literal phrases exist AND that `runTurn`'s Firestore write never carries any field beyond the locked schema, so a jailbroken `reply` string can pollute at most the spoken line, never structured data |
| T-02-02 | Spoofing / Elevation of privilege | `simulateTurn` (onCall, no Firebase Auth) | medium | accept | Reachable by any web client, but the zod input schema has no `householdId` field — it is structurally limited to the demo household (ASVS L1 requirement); acceptable for a one-night demo with no real PII behind it |
| T-02-03 | Information Disclosure | Anthropic API key | high | mitigate | `ANTHROPIC_API_KEY` bound only via `defineSecret` (Phase 1), read server-side inside `runTurn`, never logged, never reaches `apps/web` |
| T-02-SC | Tampering | `@anthropic-ai/sdk@0.127.0` npm install | low | accept | 02-RESEARCH.md's Package Legitimacy Audit already ran this session: SUS/too-new-only, canonical `anthropics/anthropic-sdk-typescript` repo, zero postinstall scripts — identical disposition to Phase 1's approved packages, no blocking checkpoint needed |
