<objective>
**As a** senior living alone with the phone nearby, **I want to** see the lamp beside my phone glow amber, blue, green, or red matching what's happening on an incoming call, and be able to press one joystick button to call my family, **so that** I never have to read anything or understand a screen to know I'm safe or need help. (User story derived from the ROADMAP Phase 3 Goal line per MVP framing — no facts invented beyond it.)

This plan builds the Pi side of that promise: a dependency-free Python service that turns raw `POST` calls into visible light, survives reboots and a dead bridge, and captures a physical button press. It runs entirely offline on the Pi (stdlib only, no `pip install`), reachable only over the direct ethernet cable at its static address `169.254.10.2:8080`.

Purpose: prove the hardware/rendering half of the phase end-to-end before Plan 02 wires Firestore to it — nothing in Plan 02 can be verified without this plan's HTTP service already responding correctly on the Pi.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Direct ethernet cable (Mac `en8` ⇄ Pi `eth0`) → Pi HTTP server | Any device physically on this point-to-point link can POST to `/state` or read `/health`/`/joystick` — no other host exists on this segment in the demo setup. |
| POST body → JSON parser → render thread | Untrusted-shaped input (arbitrary bytes from whatever is on the cable) crosses into the process here before validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | `pi/lamp.py` HTTP server (no auth) | low | accept | Reachable only over a physically direct link-local ethernet cable with no other hosts on the segment during the demo; adding auth (tokens/TLS) would be net-negative complexity for a device with no network path to a real attacker. Noted explicitly per project decision — never expose this service over Wi-Fi. |
| T-03-02 | Tampering | `do_POST /state` JSON/enum parsing | medium | mitigate | `try/except` around JSON parse + strict enum check; unknown/malformed input returns 400 and never reaches the render thread (Task 2). |
| T-03-03 | Denial of Service | HTTP server bind address | low | mitigate | Bind explicitly to `169.254.10.2:8080`, never `0.0.0.0` (ASVS V4) — the service never listens on an interface other than the trusted cable. |
| T-03-04 | Denial of Service (availability) | Render loop / bridge liveness | medium | mitigate | 60s watchdog thread forces `idle` on POST silence, independent of the bridge's health (Task 3) — a crashed bridge or unplugged cable can't leave the lamp stuck on `scam` through a live demo. |
| T-03-05 | Tampering (crash) | evdev joystick struct parsing | low | mitigate | `struct.calcsize` verified at startup before the joystick thread starts; on mismatch the thread is skipped (not started) rather than crashing, and it runs isolated from the HTTP/render threads as a daemon (Task 3). |
</threat_model>
